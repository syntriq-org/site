One platform, different business applications

Keep reusable platform mechanisms separate from the domain definitions that make each application useful.

Reuse starts with a clear boundary

An application platform becomes difficult to reuse when its core quietly assumes one industry. A generic decision service should not need a special branch for a charging settlement. A reusable chart should not hard-code an EV measure. Domain knowledge belongs in explicit application definitions.

Syntriq’s platform direction separates reusable mechanisms from domain packages. ChargeWeave supplies a concrete application through which those boundaries can be exercised.

Let the domain describe its business

The ChargeWeave package provides EV entities, relationships, constraints, versioned policies, workflows, measures and branding. These definitions describe what the application means and how its domain behaves. Registered implementations cover behaviour that needs explicit code.

The platform supplies the supported runtime contracts: querying, validation, decision evaluation, process coordination, temporal context and analytical interfaces. Its supported semantic subset must be declared rather than implying unrestricted execution of every ontology construct.

Use a correction journey as a reference

A settlement correction connects a form, typed data access, constraints, calculations, a policy decision and a workflow. It provides a useful reference journey because a change can have visible consequences across several layers.

The reusable boundary can be examined at each step. Decimal arithmetic is a generic concern; the domain defines which amounts enter the calculation. Duplicate protection is a runtime concern; the application defines the meaning of the command.

Keep engineering context portable

The catalogue and Context Engine should discover application definitions through common contracts. AI tools can then inspect the current domain package without embedding charging-specific assumptions in the coordinator. Scenarios and evidence retain their source and candidate identities.

This gives the engineering workbench a reusable shape while leaving the relevant business knowledge in the application. A different domain would provide different definitions, policies and scenarios through those interfaces.

Extract along tested seams

The technical work can continue inside ChargeWeave while the generic contracts become clearer. Extraction should move a reusable mechanism behind an established interface and exercise the same reference journeys against it.

A second domain can later help expose hidden assumptions, but the commercial site should not imply existing customers or deployed applications that have not been established. ChargeWeave is the concrete example; the broader platform proposition rests on the separation of responsibilities.

THE BUSINESS VALUE

Evolve reusable platform mechanisms while keeping industry knowledge in explicit application packages.
